Lesson 2

Scoring a Match

A computer can't see a pattern. It can only compare numbers, so it needs a score.

Laying one drawing over another

Trace a picture on see-through paper and slide it over the original. When they line up, every line sits on its partner. When they don't, you see double. SPAM does this with numbers, voxel by voxel. Remember, each voxel holds a grey value from 0 to 255.

SPAM uses two different scores. Move the slider and watch them both.

The true shift is 13 voxels. Notice what each line does there.

Score 1: the error

Think of a golf score: lower is better, and zero is perfect. Take two matching voxels, subtract, and square the answer so that minus signs can't cancel out. Add this up for every voxel in the window. A perfect match scores 0.
error = sum of (unloaded − loaded)² ÷ sum of unloaded
SPAM's _errorCalc is exactly this: nansum(square(subtract(im1, im2))) / nansum(im1). This is the error column in the ldic.tsv output file. Dividing by the sum of the window makes bright and dark windows easier to compare.

Score 2: the correlation

Press the brighter button, then move the slider. The error gets confused, but correlation doesn't care! It asks a different question: "Do the bright bits and dark bits line up?" A photo in dim light is still the same photo.
correlation = shared pattern ÷ biggest possible shared pattern

This is called normalised cross-correlation, or NCC. It runs from −1 to 1, and 1 means a perfect pattern match.

Pixel search picks the position with the highest correlation. Its code comment says values above 0.99 can generally be trusted and about 0.5 is random. Those guide values are for its search, so don't apply them to other correlation tests.

Remember this

  • Error: low is good, and it's sensitive to brightness.
  • Correlation: high is good, and it only cares about pattern.
  • Plain grey in the difference image means a good match.
