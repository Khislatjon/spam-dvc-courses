Lesson 1

Reading a Command

A command looks scary, but it's only a sentence telling the computer what to do.

It's like ordering food

Think of ordering a pizza: "One pizza, large, extra cheese, to my house." The tool is the pizza, and the flags are your choices. In a terminal, a flag starts with a dash, and usually a value follows it.

Three tools, one chain

You'll use up to three tools. Each one writes a file, and the next one reads it, like passing a baton in a relay race.

OrderToolJobWrites
1spam-regOne Phi for the whole scanname-registration.tsv
2spam-pixelSearchOptional: a rough start for each windowname-pixelSearch.tsv
3spam-ldicThe final Phi for each windowname-ldic.tsv
Notice the pattern: -pre sets the start of the name, and SPAM adds the rest. If you set -pre myrun, you get myrun-registration.tsv.

What comes out

This is what a real run printed. It shows your settings first, so read them to check your flags were understood.

spam.DIC.registerMultiscale(): working on binning: 4 Start correlation with Error = 55.52 -> Converged spam.DIC.registerMultiscale(): working on binning: 2 Start correlation with Error = 6.49 -> Converged Registration converged, great... saving

The result file is a plain table you can open in a spreadsheet. One row holds a Phi and its report card:

SPAM's tools read TIFF stacks. If your scans are DICOM or another format, convert them first. The order matters: the first image is the one that stays still, and the second is the one being deformed.

Remember this

  • A command is a tool, some inputs and some flags.
  • Each tool's output file becomes the next tool's input.
  • Always read the settings SPAM prints back to you.
